AI adoption is easy to announce and surprisingly difficult to measure. A firm that pays for a model API, a worker who occasionally uses a chatbot, and a company that redesigns an entire workflow around machine intelligence are not economically equivalent events.

## Start with the mechanism

The useful question is not simply whether a firm “uses AI.” It is which task changed, what complementary capability made that change possible, and where the value appears. A credible measure should distinguish experimentation from embedded use and exposure from realized adoption.

I organize measurement around three layers:

- **Exposure:** whether a task could plausibly benefit from current AI capabilities.
- **Adoption:** whether the organization has deployed those capabilities in a repeated process.
- **Integration:** whether decisions, roles, or capital allocation changed as a result.

## Triangulate imperfect signals

No single source is sufficient. Procurement records miss free tools. Surveys invite prestige bias. Job postings capture aspiration more readily than implementation. Website text is abundant but strategically written.

The better approach combines signals with different failure modes: structured survey responses, software spending, vacancy language, process documentation, and—in consenting research settings—aggregated usage telemetry.

> A useful index is not the one with the most data. It is the one whose errors we can explain.

## Design for falsification

Any adoption index should be validated against outcomes it did not use in construction. Do measured adopters change task composition, training expenditure, or cycle times? Do adoption dates align with qualitative implementation histories? Are results robust when promotional language is removed?

The goal is not a perfect scoreboard. It is a measurement system honest enough to support causal claims—and clear enough to improve when better evidence arrives.
